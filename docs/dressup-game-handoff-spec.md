# 캐릭터 꾸미기 게임 MVP — 인수인계 스펙

딸아이를 위한 로블록스 "입양하세요" 스타일 캐릭터 커스터마이징 게임.
아래는 챗 환경에서 도형(그레이박스) PoC로 검증을 마친 내용입니다. 클로드 코드에서는
이 스펙을 바탕으로 실제 프로젝트 구조로 새로 짜는 것을 추천합니다 (PoC 코드는 한 파일에
다 몰아넣은 프로토타입이라 그대로 이식하기보다 구조를 나눠 다시 짜는 편이 낫습니다).

작동하는 참고용 데모: (챗에서 게시한 캐릭터 리그 + 옷 갈아입히기 PoC 아티팩트 링크를 여기에 붙여넣으세요)

## 1. 목표 (MVP 범위)
- 캐릭터 1명, 걷기 애니메이션, 옷/헤어 갈아입히기, 로블록스 스타일 3인칭 조작
- 그레이박스(단순 도형)로 먼저 완성 → 나중에 실제 아트로 교체
- 과하게 확장하지 말 것: 멀티플레이, 아이템 상점, 저장 서버 등은 MVP 이후

## 2. 캐릭터 리그 구조 (핵심 — 반드시 유지)
계층형 관절(피벗) 구조. 부모가 회전하면 자식 전체가 같이 움직임.

```
hips (루트, 캐릭터 위치/이동 기준)
├─ torso (몸통 메쉬)
│  └─ head
│     ├─ eyes, nose, ears  (정면/측면 구분용, 좌우/전후 비대칭 필수)
│     └─ hair (남/여 스타일, visibility 토글)
├─ leftShoulder → leftElbow   (팔, 걷기 시 다리와 반대 위상으로 스윙)
├─ rightShoulder → rightElbow
├─ leftHip → leftKnee         (다리, 걷기 스윙 + 무릎 굽힘)
└─ rightHip → rightKnee
```

**옷은 새 지오메트리를 만드는 게 아니라, 이미 있는 관절의 자식으로 붙인다.**
절대 좌표를 따로 계산해서 덮어씌우면 안 됨 (그러면 다리가 움직일 때 옷이 안 따라감).

## 3. 옷 부착 규칙 (데이터로 분리할 것)
PoC에서는 이 부분을 하드코딩했다가 오류가 났던 지점. 처음부터 설정 객체로 분리 추천:

```js
const CLOTHING_ITEMS = {
  male_shorts: { attachTo: ['leftHip','rightHip'], strideScale: 1.0, color: 0x2f6690 },
  female_skirt: { attachTo: ['hips'], strideScale: 0.42, color: 0xd8558f },
  // 이후 옷 추가 시 이 배열에만 항목 추가하면 됨
};
```
- 하의류(바지, 반바지 등) → 다리 관절(leftHip/rightHip)에 부착 → 다리와 함께 접힘
- 치마/원피스류 → 허리 관절(hips)에만 부착 → 허리 기준으로 통째로 움직임
- `strideScale`: 옷이 보폭을 제한하는 정도 (치마=좁은 보폭, 바지=정상)
- 여러 벌 중 하나만 보이기: **배열에 참조만 저장 후 visible 토글** (Object3D.add()로
  재부착하면 원래 관절에서 떨어져 나가 버그가 남 — PoC에서 실제로 겪은 실수)

## 4. 얼굴/헤어 — 방향 구분 필수 조건
카메라를 앞/뒤/옆으로 돌렸을 때 반드시 서로 다른 실루엣이 나와야 함:
- 코: 정면(+Z)에만 튀어나옴 → 앞/뒤 구분
- 귀: 좌우 측면에만 있음 → 옆모습 구분
- 헤어: 완전한 회전체(대칭 반구, "바가지" 모양) 금지. 뒤통수 볼륨을 비대칭으로 추가하거나,
  긴 머리는 뒤쪽으로만 늘어지게 해서 앞뒤가 다르게 보이도록

## 5. 조작 방식 — 로블록스 3인칭 방식 (그대로 구현)
가장 많이 삐끗했던 부분. 아래 원칙을 코드보다 먼저 텍스트로 박아둘 것:

- **카메라 방향은 캐릭터 회전과 완전히 독립적** — 카메라는 캐릭터의 *위치*만 따라가고,
  캐릭터가 몸을 돌려도 카메라는 같이 돌지 않음 (안 그러면 캐릭터 자동회전 ↔ 카메라 추적이
  서로 되먹임 되어 빙글빙글 도는 버그가 생김)
- 화면 드래그 → 카메라가 캐릭터 주위를 궤도 회전 (우클릭 드래그 또는 모바일 터치 드래그)
- 마우스 휠 / 핀치 → 줌 인아웃
- 이동키(화살표/WASD)는 **항상 현재 화면 기준** 전/후/좌/우 (카메라가 도는 방향을 기준으로
  계산해야지, 캐릭터의 현재 orientation을 기준으로 계산하면 안 됨)
- 캐릭터는 이동하는 방향으로 **자동으로 몸을 회전** (별도의 "턴" 버튼 없음)

## 6. 검증 방법 (구현 후 반드시 실행)
"눈으로 한두 번 보고 넘어가기"는 조합이 많아지면 반드시 다시 깨짐. 다음을 자동 테스트로:
- 캐릭터 초기 방향 8가지(45도 간격) × 카메라 시점(정면/후면/좌/우/자유시점) ×
  이동 입력(상/하/좌/우) 조합 전수 검사
- 각 조합에서 "카메라 투영 상 이동 벡터가 화면에서 기대한 방향(위/아래/좌/우)으로
  나타나는가"를 좌표 계산으로 검증 (Node.js + three.js 헤드리스로 가능, PoC에서 검증한 방식)

## 7. 나중에 그레이박스 → 실제 아트로 교체할 때
- 지금은 상자/구 등 도형을 관절에 매단 "리지드 파츠" 방식 (마인크래프트/로블록스 클래식과 동일)
- 실제 캐릭터 아트로 바꿀 때 두 갈래:
  - (A) 지금처럼 부위별 분리 메쉬를 관절에 매다는 방식 유지 → 구조 거의 그대로 재사용
  - (B) 몸 전체가 이어진 메쉬 + 정점 가중치로 부드럽게 휘는 스키닝(SkinnedMesh) → 구조를
    다시 짜야 함 (Ready Player Me, VRM 아바타가 이 방식)
  - 어느 쪽으로 갈지 먼저 정하고 시작할 것

## 8. 추천 기술 스택 (MVP 규모 기준)
- Vite + 순수 Three.js (프레임워크 없이 시작, 나중에 필요하면 React Three Fiber로 이전)
- 파일 분리: `rig.js`(관절 생성) / `clothing.js`(옷 데이터+부착) / `controls.js`(로블록스식
  카메라·이동) / `scene.js`(씬 구성) 로 초반부터 나눠서 시작 — 한 파일에 다 넣으면
  나중에 옷 종류 늘릴 때마다 전체를 다시 훑어야 함

## 9. 클로드 코드에 처음 보낼 프롬프트 (초안)
> 위 스펙 문서(dressup-game-handoff-spec.md)를 참고해서 Vite + Three.js 프로젝트를
> 새로 만들어줘. 3번(캐릭터 리그), 4번(옷 부착 규칙), 6번(조작 방식)은 문서에 적힌 그대로
> 지켜줘. 먼저 캐릭터 리그와 옷 부착 데이터 구조부터 잡고, 그 다음 조작 방식을 구현한 뒤,
> 8번에 적힌 자동 검증 스크립트로 확인해줘.
